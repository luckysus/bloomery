# Bloomery Agent-first 桌面客户端界面设计

## 文档定位

本文定义 Bloomery Agent-first 桌面客户端的目标界面和交互模型。它面向 Tauri 桌面应用，使用 React 负责视图，Rust Agent Runtime 负责运行事实。打开应用后直接进入任务/对话，不经过工作台首页或多模块仪表盘。

Open Vetta 只作为 Agent 运行语义和信息组织的参考：借鉴 Turn、工具轮次、可中断运行、上下文预算和恢复等概念，形成 Bloomery 自己的桌面工作流和视觉语言，不复制 Open Vetta 的页面结构、组件或实现。

本文是设计文档，不要求立即改造现有页面，也不包含 NexusPilot 集成。它描述的是类似 Codex、Claude、Open Vetta 的智能体产品形态，但不复制任何一个产品的页面或视觉。

## 产品目标

Bloomery 的第一屏应该让用户完成三件事：

1. 直接向智能体提出任务。
2. 看懂智能体当前在做什么、为什么停下来，以及下一步可以做什么。
3. 快速回到正在运行、最近完成或需要处理的任务。

产品核心是“一个任务、一条对话、一个可观察的运行过程”。工具、权限、知识来源、文件和子 Agent 都围绕当前任务展开；知识、数据和扩展作为上下文或结果面板出现，不抢占智能体主入口。

## 设计原则

### 桌面优先

界面为 Windows 桌面窗口设计，优先支持宽屏、键盘操作、拖放文件和长时间运行任务。窗口不模拟网页首页，不使用营销式 Hero，不依赖远程页面才能工作。

### 运行状态可见

每次 Agent Run 都有明确的状态、阶段、耗时、当前动作和可执行控制。用户不需要猜测“它是不是卡住了”。

### 对话与任务统一

一个对话可以产生多个 Run、后台任务和子 Agent。用户从消息、任务中心或恢复提示进入同一个运行详情，而不是看到互相矛盾的状态副本。

### 证据靠近结论

引用、工具结果和来源位置在回答旁边可打开；详细内容放入右侧检查器，避免把主对话变成日志墙。

### 可中断、可恢复

停止、转向、追加、重试和恢复是正常操作。危险工具需要权限卡片，取消不会被伪装成失败。

### 安静而有层次

视觉使用中性背景、单一暖色强调和明确的成功/警告/错误颜色。重要状态依靠文字、图标和布局共同表达，不只依靠颜色。

## 总体窗口结构

推荐窗口尺寸为 `1440 × 900`，最低可用尺寸为 `1180 × 720`。窗口采用 Agent-first 的三栏结构：

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ 会话标题 / 项目 / 模型 / 搜索 / 运行状态 / 菜单                              │
├──────────────────────┬──────────────────────────────────┬───────────────────┤
│ 会话与项目侧栏        │ 主对话区                          │ 上下文与运行检查器  │
│ 280–320px             │ minmax(620px, 1fr)                │ 320–380px，可收起   │
│                      │ 消息、工具摘要、输入区             │ 文件、步骤、来源     │
└──────────────────────┴──────────────────────────────────┴───────────────────┘
```

### 顶部标题栏

标题栏高度 56px，左侧是产品标识和当前会话标题，中间显示项目/工作区与模型快照，右侧提供搜索、运行状态、命令面板和窗口菜单。它不承担一级模块导航。

运行中的 Agent 在标题栏保留一个小型状态提示，例如“运行中”“需要授权”或“已恢复”。点击提示打开当前 Run 的检查器。

### 会话与项目侧栏

侧栏是应用的主要导航，内容固定围绕 Agent：

- 新建任务。
- 搜索会话和文件。
- 项目/工作区列表。
- 当前项目的会话、置顶项和最近任务。
- 运行中的任务和草稿。
- 底部设置、帮助和版本信息。

侧栏可以收起到 56px 图标栏，也可以在 280px 和 320px 之间调整。收起后仍保留新建任务、搜索和当前会话入口。

### 主对话区

主对话区是默认且最大的区域，承载用户消息、助手回答、工具摘要、子 Agent 进度和输入区。内容滚动只影响对话，不带动侧栏和检查器。

### 上下文与运行检查器

右侧检查器默认在 Run 活动、用户打开来源或存在待授权操作时出现，空闲时收起。它显示当前任务的结构化信息：Run 状态、Turn、上下文预算、工具、子 Agent、权限、文件、来源、恢复和错误。检查器不是第二个聊天窗口，不允许在这里编辑消息。

## 信息架构

### 会话和项目

会话是最小的用户工作单元，项目/工作区只负责提供默认上下文、文件边界、模型偏好和工具集合。打开项目时直接打开最近会话或新任务输入框。

### 当前任务和 Run

一个会话可以有多个 Run。运行中的 Run、暂停的 Run、失败的 Run 和可恢复的 Run 都在当前会话内显示，任务中心只是跨会话查看这些 Run 的抽屉，不是独立首页。

### 文件、知识和工具上下文

知识库、数据集、Wiki、MCP 和 Skills 通过上下文选择器、附件、来源面板或命令面板进入当前任务。用户不需要离开对话才能把一个来源加入下一次 Run。

### 设置与扩展

设置和扩展是低频页面，通过侧栏底部或命令面板打开。它们展示持久化配置、能力、权限、版本和健康状态；当前 Run 实际使用的快照仍在检查器中查看。

## Agent 工作区

### 页面布局

```text
┌────────────────────────────────────────────────────────────────────┐
│ 会话标题     模型 · 工作区 · 本地运行                         ⋯  │
├────────────────────────────────────────────────────────────────────┤
│ 运行状态条：准备中 / 思考中 / 工具运行中 / 需要授权 / 已完成      │
├────────────────────────────────────────────────────────────────────┤
│                                                                    │
│ 用户消息                                                          │
│                                                                    │
│ 助手回答  [引用 1] [引用 2]                                      │
│   可展开的思考摘要                                                 │
│   工具时间线 / 子 Agent 进度 / 结果摘要                            │
│                                                                    │
│ 用户消息                                                          │
│                                                                    │
├────────────────────────────────────────────────────────────────────┤
│ 附件/上下文条                                                     │
│ 多行输入框                                  模型  发送 / 停止      │
└────────────────────────────────────────────────────────────────────┘
```

### 会话头部

会话头部展示标题、当前模型、工作区和连接状态。模型切换只影响下一次 Run；运行中的 Run 显示启动时固定的模型快照。

右侧提供搜索消息、导出和打开检查器。删除、归档等低频操作进入菜单，不占用固定按钮位。

### 消息时间线

消息时间线按用户 Turn 分组。每个用户 Turn 下方显示对应的助手回答和运行过程：

- 回答正文默认展开。
- 思考内容默认折叠，只显示“已生成思考摘要”和耗时。
- 工具调用默认显示名称、状态、耗时和一行结果摘要。
- 长结果保存为本地产物，点击后在检查器或独立查看器中打开。
- 引用显示编号、来源名称和位置；点击在右侧打开原文预览。
- 子 Agent 使用缩进树显示，显示任务名、状态、结论摘要和子 Turn ID。

回答流式生成时，内容区域保持稳定高度策略，输入框和右侧检查器不随单个 token 跳动。

### 输入区

输入区固定在主工作区底部，支持：

- 多行文本和 `Enter` 发送、`Shift + Enter` 换行。
- 文件拖放、粘贴图片和附件移除。
- 当前工作区/知识库上下文标签。
- 模型选择。
- 停止、转向和追加。

运行中输入区不被整体禁用：停止始终可用；转向只在当前 Run 仍可接受 Steering 时显示；追加消息进入 Follow-up 队列并标记“本轮结束后发送”。

## Run 状态和操作

### 状态集合

| 状态 | 用户看到的含义 | 可用操作 |
| --- | --- | --- |
| `created` | 已创建，等待调度 | 取消 |
| `preparing` | 正在准备上下文和工具快照 | 取消 |
| `generating` | 模型正在生成 | 停止、转向、追加 |
| `tool_running` | 一个或多个工具正在执行 | 查看、取消 Run |
| `awaiting_permission` | 等待用户授权 | 允许一次、允许本次会话、始终允许、拒绝 |
| `recovering` | 正在从 checkpoint 恢复 | 取消、查看恢复详情 |
| `paused` | 用户或系统暂停 | 恢复、取消 |
| `completed` | 已完成 | 复制、继续、导出 |
| `failed` | 已失败 | 查看错误、重试、复制诊断 ID |
| `cancelled` | 已取消 | 继续、重新运行 |
| `interrupted` | 应用或窗口中断 | 恢复、重试、取消 |

状态条只展示一个主状态，详细阶段放入检查器。每个终态必须带完成原因或可操作的后续动作。

### 工具时间线

工具卡片使用统一结构：

```text
工具名称  · 只读/写入 · 版本
输入摘要                                      00:02
权限：已允许 / 等待授权 / 已拒绝
结果摘要或错误码
```

工具卡片只默认显示经过脱敏和截断的摘要。完整输出通过本地产物或诊断详情打开，不能把凭据、完整环境变量或不受控的大文本塞进消息流。

### 权限卡片

权限卡片必须说明：动作、目标、影响范围、调用来源和有效期。按钮文案使用“允许一次”“允许本次会话”“始终允许”“拒绝”，不使用没有含义的“确定”。

### 子 Agent

子 Agent 在消息时间线显示简短进度，在检查器显示完整树：

```text
父 Turn
├─ 检索相关文档        已完成  12s
├─ 分析数据异常        运行中  8s
└─ 汇总结果             等待子任务
```

父 Run 可以取消全部子任务；用户也可以在检查器中单独取消某个仍在运行的子 Turn。子 Agent 不能在 UI 中获得高于父 Run 的权限。

## 右侧运行检查器

检查器使用标签页，但同一时间只保留一个主标签：

1. **概览**：状态、耗时、模型、上下文预算和本轮摘要。
2. **步骤**：模型调用、工具调用、权限和子 Agent 时间线。
3. **来源**：引用、证据包、文档页码、表格范围和 Wiki 页面。
4. **恢复**：checkpoint、重连、重试次数和恢复动作。
5. **错误**：稳定错误码、脱敏诊断信息和建议动作。

上下文预算用数值和简单条形显示，至少分为系统规则、工具 Schema、历史消息、当前请求、输出预留和推理预留。预算超限时显示裁剪原因和被保留的内容类别。

## Agent 起始状态

应用没有独立的工作台首页。启动后按以下顺序选择目标：

1. 如果存在可恢复的活动 Run，先在当前会话顶部显示恢复条。
2. 如果存在最近会话，打开最近一次会话并把输入焦点放在编辑区。
3. 如果没有会话，打开新任务页面，直接显示输入框、项目选择、模型选择和附件入口。

新任务页面只保留必要操作：选择项目、选择模型、添加文件或知识来源、输入任务。模型未配置时，输入区旁显示配置入口；不做无内容的欢迎仪表盘。

任务中心以侧栏抽屉或命令面板结果出现，展示跨会话 Run 和后台任务。它不替代当前对话，也不成为默认首页。

## 视觉语言

### 色彩

使用三层 Token：原始色、语义色、组件色。建议语义色如下：

| 语义 | 亮色 | 暗色 | 用途 |
| --- | --- | --- | --- |
| 页面背景 | `#F7F7F4` | `#171817` | 窗口和主工作区 |
| 提升背景 | `#FFFFFF` | `#222421` | 输入区、检查器、浮层 |
| 线条 | `#E3E5E0` | `#393D38` | 分隔和边界 |
| 主文字 | `#20231F` | `#F0F2ED` | 标题和正文 |
| 次文字 | `#667068` | `#A5AEA4` | 辅助说明 |
| 主强调 | `#B86E45` | `#E39A6A` | 当前状态、主要操作 |
| 成功 | `#3E846D` | `#76C09F` | 已完成、在线 |
| 警告 | `#B88336` | `#E6B869` | 等待、降级 |
| 错误 | `#B64B4B` | `#EE8585` | 失败、拒绝 |

强调色只用于交互和状态，不把整块页面染成单一色系。禁止用渐变、装饰性光球和大面积阴影制造层次。

### 间距、圆角和阴影

- 基础间距为 4px，常用间距为 8、12、16、20、24、32px。
- 普通控件圆角 6px；输入区、对话卡片和检查器圆角 8px；避免超过 12px。
- 页面分区依靠留白和 1px 边界，不使用卡片套卡片。
- 阴影只用于菜单、对话框和拖拽浮层；主布局保持平面。

### 字体

- 中文和界面：Inter、Noto Sans SC、系统无衬线。
- 代码、ID、耗时和诊断：JetBrains Mono 或系统等宽字体。
- 正文基准 14px，消息正文 15px，页面标题 20–24px。
- 字母间距保持默认，不用压缩字距换取视觉密度。

## 交互和快捷键

### 全局快捷键

| 快捷键 | 行为 |
| --- | --- |
| `Ctrl/Cmd + K` | 打开命令面板 |
| `Ctrl/Cmd + N` | 新建对话 |
| `Ctrl/Cmd + Shift + P` | 打开任务中心 |
| `Ctrl/Cmd + F` | 搜索当前会话或当前模块 |
| `Esc` | 关闭浮层、检查器或取消输入焦点 |
| `Ctrl/Cmd + Enter` | 发送消息 |

### 命令面板

命令面板用于 Agent 客户端动作：新建任务、切换项目、恢复 Run、打开文件/知识来源、重试任务、切换主题、打开设置和导出当前上下文。命令结果必须标明作用范围，危险动作显示影响范围后再进入权限流程。

### 通知

通知只用于后台任务完成、失败、需要授权和恢复失败。流式 token、普通工具进度和已读状态不产生系统级通知，避免干扰。

## 启动、恢复和异常

### 首次启动

启动向导使用单列步骤页：选择数据目录、配置聊天模型、选择可选知识服务、确认权限策略。每一步都可以跳过，但跳过后要显示明确的降级状态和入口。

### 重新打开窗口

窗口启动后先恢复本地 Runtime 状态，再渲染最近会话或新任务页面。存在活动 Run 时，当前会话顶部出现“恢复运行”区域，点击后进入原会话并按 sequence 补齐事件。

### 断线

Tauri 事件监听断开时，主工作区显示轻量的“正在重新连接”状态；重连后使用最后确认的 sequence replay。重复事件不重复创建消息、工具卡片或通知。

### Provider 或工具失败

错误卡片显示稳定错误类别、简短原因、诊断 ID 和下一步动作。用户可以查看脱敏详情、重试当前步骤或回到对话继续。错误堆栈不直接占据主内容区域。

## 无障碍和可用性验收

- 所有图标按钮有可访问名称；只显示图标时必须有悬停提示。
- 键盘可以在会话侧栏、主对话区和检查器之间移动。
- 焦点环使用语义强调色，不能只依赖颜色表示焦点。
- 运行状态同时使用文字、图标和结构变化表达。
- 支持系统减少动效设置；流式更新不使用持续闪烁。
- 文字在最小窗口尺寸下不溢出按钮、卡片或检查器。
- 100% 和 125% Windows 显示缩放下，输入区、工具卡和侧栏仍保持稳定尺寸。

## 实现边界

### 前端负责

- 布局、导航、事件 reducer、消息渲染和检查器交互。
- 根据 `agent-event` sequence 投影视图。
- 展示权限请求并调用授权命令。
- 展示和操作 Run、子 Turn、任务和恢复动作。

### Rust Runtime 负责

- Run/Turn 状态、模型和工具快照、上下文预算、checkpoint、恢复和取消。
- 工具执行、权限判定、子 Agent、事件持久化和 sequence。
- 为前端提供重放、控制和查询命令。

### 不在本设计范围

- NexusPilot 的页面或组件嵌入。
- 远程 Web 端登录和云端会话。
- 通过兼容层保留旧网页入口。
- 为了视觉复刻 Open Vetta 而复制其代码或页面。

## 实现顺序

1. 建立 Token、窗口骨架、会话侧栏和顶部上下文栏。
2. 实现 Agent 对话：新任务、会话列表、消息时间线、输入区和基础 Run 状态条。
3. 实现右侧运行检查器：步骤、工具、权限、子 Agent、文件、来源和恢复。
4. 实现任务抽屉，让跨会话 Run 与后台任务使用同一状态模型。
5. 实现项目/工作区上下文选择器，以及知识、数据和扩展的详情面板。
6. 接入命令面板、快捷键、通知、启动恢复和断线 replay。
7. 完成 Windows 最小窗口、缩放、键盘、减少动效和端到端验收。

## 验收标准

1. 用户打开应用后无需进入网页页面即可创建 Agent Run。
2. 用户可以在同一界面看到回答、工具进度、权限请求、子 Agent 和来源。
3. 用户可以停止、转向、追加、恢复、重试和取消对应的 Run。
4. 刷新窗口或重连后，已持久化事件按 sequence 恢复且不重复。
5. 任务抽屉能够统一显示对话 Run、知识导入、索引和数据分析任务，并能返回原始会话。
6. 最小窗口和 125% 缩放下没有文本、按钮或检查器重叠。
7. 所有错误和权限提示都给出用户可执行的下一步。
8. 前端只消费 Rust Runtime 的事件和命令，不维护第二套运行事实。
