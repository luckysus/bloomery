# Bloomery 正式发布版产品与技术设计

日期：2026-07-29
状态：已确认的总体设计，等待规格审阅
目标版本：首个公开正式版（不是 MVP、Alpha 或功能阉割版）

## 1. 文档目的

本文定义 Bloomery 首个公开正式版的产品边界、系统架构、核心流程、安全模型、质量门槛和发布标准。后续实施可以按依赖关系分阶段进行，但任何中间阶段都不代表正式版完成。只有本文列出的完整能力和发布门槛全部通过，才能发布正式版。

本文同时约束一项关键迁移原则：Bloomery 是与 Steel Agent Web 应用完全解耦的独立桌面产品。现有代码可以作为可验证资产复用，但不能为了保留旧实现而继续引入登录、自有后端、云任务或 Web API 兼容层。

## 2. 产品定义

Bloomery 是一个本地优先、Windows 优先、可扩展的领域智能体工作台。产品由通用智能体核心和可安装领域包组成，官方首个领域包聚焦钢铁与材料工程。

Bloomery 不是第 N 个通用聊天客户端。它的核心价值是：

- 在用户自己的电脑上管理对话、文档、索引、记忆、生产数据和任务。
- 将领域知识检索、结构化工具、生产数据分析和智能体推理组合为可审计工作流。
- 允许用户自行选择 LLM、Embedding、Reranker 和文档解析服务。
- 通过 MCP、Skills 和领域包扩展能力，而不绑定 Bloomery 自有服务器。
- 为 Windows 工业用户提供安装、配置、恢复、诊断和更新都完整的桌面体验。

### 2.1 目标用户

- 钢铁企业的工艺、质量、研发和生产数据人员。
- 材料领域研究人员和工程师。
- 希望构建化工、机械等其他领域包的开源贡献者。
- 需要本地数据控制，但允许直接调用所选模型服务商的个人或团队。

### 2.2 产品边界

正式版明确不做以下事情：

- 不提供 Bloomery 账号、登录、会员、管理员后台或团队云空间。
- 不依赖 Steel Agent Web、Bloomery 私有 API 或作者控制的中转服务器。
- 不把终端编码、补丁生成和代码仓库自动化作为核心产品定位。
- 不执行领域包中携带的任意二进制或脚本；可执行扩展必须通过受控 MCP 接口。
- 不在应用数据库、日志、诊断包或导出包中明文保存 API Key。
- 不承诺完全离线调用第三方云模型；完全离线能力由用户配置的本地 Provider 决定。
- 不为了兼容旧 Web 页面而保留重复业务流程或两套数据源。

## 3. 架构决策

### 3.1 选择的路线

采用“保留 Bloomery 桌面外壳，重建 Rust 智能体内核”的路线：

- 保留 Tauri 2、React、SQLite、已有窗口能力和经过验证的桌面交互组件。
- 逐项评估现有会话、消息、设置和流式显示代码；满足新边界的代码直接迁移。
- 删除登录、用户资料、管理员设置、Web API 服务和云任务镜像。
- 将当前集中式本地智能体拆成可独立测试的 Rust 模块。
- 不直接 fork OpenCode、Grok Build、DeepSeek-Reasonix、Pi 或 Goose。
- 只复用经过许可证、Windows 支持、边界和维护成本审查的小型通用代码。

选择该路线的原因是：直接 fork 编码智能体会继承终端、仓库、补丁和 Shell 优先的产品假设；完全从零重写又会浪费现有桌面资产。保留外壳、重建内核能够同时控制长期架构和交付成本。

### 3.2 技术栈

- 桌面容器：Tauri 2。
- 核心运行时：Rust 2021，后续升级 edition 必须单独评估。
- UI：React 18 + TypeScript + Vite。
- 权威数据存储：SQLite，使用 WAL、外键和显式迁移。
- 关键词检索：SQLite FTS5。
- 向量检索：独立版本化 HNSW 索引文件，提供 Flat 精确检索回退。
- HTTP：`reqwest` + rustls。
- 序列化协议：Serde，所有跨边界结构带显式版本。
- 密钥：操作系统凭据库；Windows 使用 Credential Manager。
- 开源许可证：Apache-2.0；第三方代码和资源维护完整 notices。

### 3.3 总体边界

```text
React UI
  -> Tauri command/event adapter
    -> versioned protocol
      -> Rust agent runtime
        -> context / tools / permissions / RAG / domain packages
          -> providers / MCP / local storage / persistent tasks
```

React 只负责交互、展示和短生命周期界面状态。业务规则、服务商调用、权限判断、任务恢复、索引和持久化全部位于 Rust。前端不得直接持有完整 API Key，也不得直接调用外部服务商。

## 4. Rust 模块设计

目标目录按职责划分如下：

```text
src/
  app/                 Tauri 启动、命令注册、依赖装配
  agent/
    runtime/           Agent loop、调度、取消、恢复
    protocol/          跨前后端事件和命令协议
    context/           上下文预算、摘要、证据与记忆组装
    session/           会话、轮次和运行生命周期
  providers/
    llm/               OpenAI-compatible、本地 Provider
    siliconflow/       Embedding 与 Reranker
    mineru/            PDF 解析任务
  rag/
    ingest/            导入、哈希、格式识别
    parse/             文档解析与规范化
    chunk/             结构感知分块
    retrieve/          FTS、向量、融合和过滤
    rerank/            重排和降级
    citation/          引用定位与证据包
  tools/
    registry/          工具定义、Schema 和发现
    execution/         执行、超时、取消和结果限制
    permission/        权限策略与确认
    builtin/           内置确定性工具
  mcp/                 MCP 连接、发现、调用和健康检查
  skills/              Skills 发现、解析、合并和注入
  domains/             领域包安装、校验、激活和版本管理
  tasks/               持久化后台任务和恢复
  storage/
    database/          SQLite 连接和事务
    migrations/        顺序迁移和兼容检查
    secrets/           OS 凭据库
    vectors/           HNSW 与 Flat 索引
    backup/            导入、导出和恢复
  diagnostics/         脱敏日志、健康检查和诊断包
```

依赖方向必须保持单向：叶子模块不能依赖 Tauri；领域包不能绕过工具注册表；Provider 不能直接写 UI 事件；SQLite 访问只能通过 storage/repository 边界。使用结构测试限制反向依赖和过大文件。

## 5. 配置、密钥和网络模型

### 5.1 配置分层

配置分为三类：

1. 非敏感配置存入 SQLite：Provider 类型、Base URL、模型 ID、超时、代理、索引参数和界面偏好。
2. 敏感配置存入 OS 凭据库：API Key、Bearer Token 和 MCP HTTP 凭据。
3. 可移植声明存入 JSON：领域包清单、Skills、MCP 非敏感连接定义和导出清单。

数据库只保存凭据引用 ID，不保存凭据值。前端获取到的只是“已配置/未配置”和脱敏末尾标识。诊断和日志层在序列化前统一脱敏，不依赖调用者主动遮盖。

### 5.2 Provider 模型

正式版支持以下 Provider 能力接口：

- `ChatProvider`：流式聊天、工具调用、用量和能力声明。
- `EmbeddingProvider`：批量向量、维度、最大批量和模型标识。
- `RerankProvider`：查询、候选、分数和最大文档数。
- `DocumentParserProvider`：提交、查询、取消和获取解析产物。

OpenAI-compatible 是默认通用 LLM 协议，同时提供 Ollama 等本地服务预设。Provider 必须先声明能力，Agent 不根据供应商名称猜测工具调用、JSON 模式或上下文窗口支持。

### 5.3 SiliconFlow

SiliconFlow 由用户直接配置并调用。Bloomery 提供：

- API Key、本地凭据保存和连接测试。
- `BAAI/bge-m3` Embedding 推荐预设。
- `BAAI/bge-reranker-v2-m3` Reranker 推荐预设。
- 免费/Pro 标签、模型 ID 和能力说明。
- 自定义模型 ID，以适应服务商目录变化。
- 请求限流、指数退避、批处理和用户可见的配额错误。

免费与 Pro 共享同一代码路径。Bloomery 不代理计费、不判断用户订阅，只根据用户选择的模型和服务商响应工作。

### 5.4 MinerU

MinerU 采用持久化异步任务模型：

1. 计算源文件哈希并建立导入记录。
2. 上传或提交解析任务。
3. 持久化远端任务 ID、状态、重试时间和来源文档。
4. 后台轮询，应用退出后停止；下次启动继续。
5. 下载并校验产物。
6. 规范化 Markdown、标题、页码、表格、图片和版面引用。
7. 完成分块和索引，原子切换文档活跃版本。

任务支持取消、有限重试、明确的永久失败状态和手动重试。任何部分成功产物都不能覆盖当前可用文档版本。

## 6. 本地 RAG

### 6.1 数据流

```text
文件选择
  -> 哈希去重与格式检测
  -> 本地解析或 MinerU
  -> 规范化 Document AST
  -> 结构感知分块
  -> Embedding
  -> SQLite 元数据 + FTS5 + HNSW
  -> 查询改写与过滤
  -> BM25 + dense retrieval
  -> RRF 融合
  -> Reranker
  -> Evidence Pack
  -> 带引用回答
```

### 6.2 文档和分块

正式版支持 PDF、Markdown、TXT、DOCX、HTML、CSV 和 XLSX。PDF 优先使用 MinerU；当用户未配置 MinerU 时，提供本地文本层解析并明确显示质量差异。

每个分块必须保存：

- 文档 ID、版本 ID 和内容哈希。
- 页码或工作表、标题路径和块序号。
- 规范化文本和原始片段定位。
- 表格、图片或公式类型。
- Embedding 模型、向量维度和索引版本。
- 可见范围、领域包和用户标签。

分块以标题、段落、表格和页边界为优先，Token 长度为限制。表格不应按普通换行任意切断；超大表格保存摘要块和行窗口块。

### 6.3 混合检索

- FTS5 提供 BM25 关键词召回。
- HNSW 提供语义召回。
- Reciprocal Rank Fusion 合并不同分数空间。
- Metadata filter 在召回前尽可能下推。
- Reranker 对有限候选进行最终排序。
- Reranker 不可用时使用融合分数降级，不阻断问答。

默认参数由领域包提供，用户可以在高级设置中覆盖。每次回答保存最终证据集合、分数、来源和配置快照，保证可审计。

### 6.4 向量索引生命周期

SQLite 是权威数据；HNSW 是可以重建的派生文件。索引文件带格式版本、模型 ID、向量维度、文档集合水位和校验和。

- 应用启动时检查索引与数据库水位。
- 小规模变更增量写入。
- 模型或维度变化创建新索引，不原地覆盖旧索引。
- 新索引完成并校验后原子切换。
- 构建失败时继续使用旧索引并显示状态。
- HNSW 不可读时使用 Flat 检索或触发可恢复重建。

## 7. Agent Runtime

### 7.1 运行循环

每次 Agent Run 使用持久化状态机：

```text
created -> preparing -> generating -> awaiting_permission
        -> executing_tools -> verifying -> completing
        -> completed | cancelled | failed | interrupted
```

运行步骤为：加载会话和设置、组装预算上下文、调用模型、校验工具调用、请求权限、执行工具、追加观察、验证回答、保存结果。状态变更和关键事件在发送给 UI 前先持久化，避免 UI 已显示但数据库未保存。

只读且互不依赖的工具可以有限并行；写入、Shell、同一资源操作和声明依赖的工具严格串行。所有工具有超时、取消令牌、输出大小限制和结构化错误。

### 7.2 上下文与记忆

上下文预算按以下优先级分配：

1. 系统规则、领域包和安全策略。
2. 当前用户请求与必要会话消息。
3. 获准的工具结果和引用证据。
4. 用户明确保存的长期记忆。
5. 历史摘要和低优先级上下文。

短期记忆是会话内消息和运行状态；长期记忆是用户可查看、编辑和删除的事实记录。模型提出的记忆候选必须经过去重、来源记录和可配置确认，不能静默写入不可见画像。

长会话摘要保留已确认结论、未完成任务、重要实体和引用，不保留无来源推测。原始消息始终保留，摘要只是派生上下文。

### 7.3 Tool-Call Repair

工具调用进入执行前依次执行：

1. 提取工具名称和参数。
2. 严格 JSON 解析。
3. 仅做无歧义的语法修复。
4. 按 JSON Schema 校验和类型规范化。
5. 将具体校验错误反馈给模型，最多重试两次。
6. 仍失败则终止该工具调用并生成用户可见错误。

修复层不能猜测危险参数、路径、命令或权限意图。任何修复后的调用仍需经过正常权限判断。

### 7.4 事件协议

公开 `PROTOCOL.md`，并使用版本化 Serde tagged enum 实现。事件至少包含：

- `run.created`、`run.state_changed`、`run.completed`。
- `message.delta`、`message.completed`。
- `tool.requested`、`tool.started`、`tool.progress`、`tool.completed`。
- `permission.requested`、`permission.resolved`。
- `evidence.attached`。
- `usage.updated`。
- `task.progress`。
- `error.raised`。

每个事件包含协议版本、事件 ID、run ID、会话 ID、顺序号和时间戳。UI 按 run ID 与顺序号去重和补序。破坏性协议变更必须增加主版本并提供迁移期。

## 8. 工具与权限

### 8.1 工具定义

每个工具必须声明：名称、稳定 ID、版本、描述、输入 Schema、输出 Schema、风险等级、是否只读、并发策略、默认超时和来源。

内置工具通过 Rust trait 实现；MCP 工具转换为相同的内部定义。Agent 只能调用已注册、已启用且适用于当前领域的工具。

### 8.2 权限等级

- `automatic`：只读、低风险、限定范围内自动执行。
- `confirm`：写文件、外部网络、生产数据变更等每次或按规则确认。
- `dangerous`：Shell、任意路径写入、删除、外部副作用，默认禁用。

确认结果支持：仅本次、当前会话、对该工具和范围始终允许、拒绝。永久规则必须可查看和撤销，并记录工具 ID、参数范围和来源，不能只按显示名称授权。

Windows 文件访问使用规范化绝对路径和授权根目录检查，拒绝路径穿越、符号链接越界和设备路径。工具执行后的真实目标仍需复核。

## 9. MCP 与 Skills

### 9.1 MCP

正式版支持：

- 本地 stdio transport。
- Streamable HTTP transport。
- 兼容旧 MCP SSE transport。
- 工具、资源和提示词发现。
- 连接健康检查、超时、重连和手动重启。
- 环境变量与 HTTP 凭据安全注入。
- 每服务器和每工具权限策略。
- 脱敏日志与调用轨迹。

优先使用成熟标准 Rust MCP SDK。只有当 SDK 缺少必要 Windows 能力时才实现薄适配层，不复制上游大型内部 MCP 架构。

### 9.2 Skills

Skills 从 `~/.bloomery/skills/<name>/SKILL.md` 加载。Skill 解析结果包含名称、描述、正文、来源和兼容要求。

Skills 是提示和流程说明，不自动获得文件、Shell 或网络权限。冲突按明确优先级合并，并在运行详情中显示实际启用的 Skills。解析失败的 Skill 被隔离并显示错误，不影响其他 Skills。

## 10. 领域包体系

### 10.1 包内容

领域包是带版本和校验的声明式目录或归档，包含：

- `manifest.json`：ID、版本、兼容范围、作者和许可证。
- 系统提示词与领域行为规则。
- 术语、同义词、牌号别名和单位定义。
- 分块、召回、重排和引用策略。
- 内置工具启用清单与参数预设。
- MCP 推荐配置，但不包含用户凭据。
- 数据导入字段映射。
- 评估数据和期望行为。
- 可选图标与界面元数据。

领域包不得携带自动执行代码。需要执行能力时，包只能声明受权限系统管理的 MCP 依赖。官方包发布时提供签名和哈希；第三方未签名包明确标记来源。

### 10.2 官方钢铁领域包

正式版钢铁包包含：

- 钢种、牌号、成分、工序、缺陷、标准和单位术语体系。
- 国标、行标、企业标准和论文的检索策略。
- 钢号别名、标准版本和等效牌号辅助匹配。
- 成分与单位换算、碳当量等确定性计算工具。
- CSV/XLSX 生产数据导入、字段映射、类型检查和缺失值报告。
- 炼钢、精炼、连铸、加热、轧制等工序数据组织。
- 质量异常和缺陷原因分析工作流，所有结论保留证据来源。
- 约束条件下的参数预测、敏感性分析和工艺优化。
- ONNX 模型导入与本地推理。
- 官方本地计算扩展，用于训练和复杂优化；它作为独立、可更新、受权限管理的本地组件发布，不依赖私有云。
- 覆盖问答、引用、计算、数据分析和优化的版本化评估集。

预测和优化结果必须标注模型版本、输入范围、约束、置信信息和适用性说明，不能表现为未经验证的生产指令。

## 11. 本地数据模型

SQLite 至少包含以下逻辑实体：

- `schema_migrations`
- `settings`、`provider_profiles`、`secret_references`
- `conversations`、`messages`、`agent_runs`、`run_events`
- `tool_calls`、`permission_rules`
- `memories`、`conversation_summaries`
- `knowledge_bases`、`documents`、`document_versions`
- `document_assets`、`chunks`、`chunk_embeddings`
- `citations`、`retrieval_runs`
- `background_tasks`、`task_attempts`
- `mcp_servers`、`skills`、`domain_packages`
- `datasets`、`dataset_columns`、`models`、`analysis_runs`

所有业务主键使用稳定 UUID；时间统一保存 UTC；UI 按本地时区展示。删除知识库、文档、会话或数据集前必须展示影响范围。涉及大量数据的删除使用可恢复任务并在事务边界内更新权威状态。

数据库迁移只能向前执行，每次启动前备份 schema 元数据。新版本不能打开更高版本数据库并继续写入；应进入只读兼容提示，防止降级损坏。

## 12. UI 信息架构

### 12.1 主导航

- 工作台：最近会话、进行中任务、知识库状态和 Provider 健康状态。
- 对话：智能体对话、证据抽屉、运行时间线和权限请求。
- 知识库：文档、解析、索引、失败任务和引用预览。
- 数据分析：数据导入、字段映射、统计、预测和优化。
- 扩展：MCP、Skills 和领域包。
- 设置：模型服务、数据目录、代理、权限、更新和外观。
- 诊断：系统信息、任务、数据库、索引和脱敏日志。

界面应面向高频工业工作流，保持安静、紧凑和可扫描。对话不是唯一首页；知识状态、任务状态和最近工作必须在第一屏可见。

### 12.2 首次启动

首次启动没有登录页，流程为：

1. 选择或接受默认本地数据目录。
2. 选择 LLM Provider，填写并测试凭据。
3. 配置 SiliconFlow Embedding/Reranker，允许暂时跳过。
4. 配置 MinerU，允许暂时使用本地基础解析。
5. 安装并激活官方钢铁领域包。
6. 完成第一次对话或导入第一份文档。

跳过可选服务不会制造假成功。相关功能显示降级状态和具体补全入口。

### 12.3 核心交互

- 流式回答不会因工具进度或长引用导致布局跳动。
- 工具调用以时间线显示输入摘要、权限、进度、结果和错误。
- 引用可打开到 PDF 页码、表格工作表或源文本位置。
- 后台任务可暂停、取消、重试，并在重启后继续。
- 模型、知识库、领域包和 Skills 的实际生效配置在运行详情中可见。
- 所有危险动作有明确影响描述，不使用含糊的“确定”按钮。

## 13. 导入、导出、备份与诊断

### 13.1 导出

- 会话导出为 Markdown、JSON 和打印友好的 PDF。
- 知识库导出包含清单、原文可选项、解析结果和索引重建信息。
- 完整备份包含数据库、文档、资产、领域包和配置，但永不包含 API Key。
- 导出清单记录格式版本、文件哈希和 Bloomery 版本。

### 13.2 恢复

恢复先校验清单和哈希，再导入到临时位置，通过数据库与索引检查后原子替换。失败时保留原数据并输出可操作错误。跨版本恢复通过数据库迁移完成。

### 13.3 诊断

诊断页检查：数据库完整性、迁移版本、索引水位、后台任务、Provider 连接、MCP 状态、磁盘空间和应用版本。诊断包默认只包含脱敏日志、版本和健康结果；用户必须显式勾选才能附加配置，且仍不包含凭据。

## 14. 错误处理与恢复

错误采用稳定错误码和面向用户的解决建议，不把底层堆栈直接作为主要提示。错误至少区分：配置、认证、配额、网络、解析、索引、模型能力、工具权限、MCP、数据库和内部错误。

恢复原则：

- 短暂网络错误使用带抖动的指数退避，遵守服务商 Retry-After。
- 用户取消不能被记录为失败。
- 后台任务每个可恢复步骤写入检查点。
- 数据库写入失败时不发送成功事件。
- Provider 流中断保留已接收内容，并允许从该轮重新生成。
- 工具输出过大时保存完整本地产物，只向模型发送有边界的摘要。
- 不可恢复错误提供诊断 ID，但日志仍需脱敏。

## 15. 安全与隐私

- 默认遥测关闭；正式版不要求遥测才能运行。
- 外部网络请求只能来自已配置 Provider、用户启用的 MCP 或更新检查。
- 发布测试包含“无 Bloomery 自有服务器流量”的网络断言。
- 更新清单和安装包必须签名并校验。
- 官方 Windows 发布包使用 Authenticode 或等效可信签名方案。
- API Key 进入 HTTP Header 前不写日志，错误响应经过密钥模式扫描。
- HTML/Markdown 渲染禁止危险脚本和未经允许的远程资源加载。
- PDF、DOCX、XLSX 和领域包解析在资源限制下运行，防止压缩炸弹和超大输入。
- MCP 子进程的环境变量采用最小注入，不继承无关敏感凭据。
- 依赖锁定并生成 SBOM、许可证清单和漏洞扫描报告。

## 16. 测试与质量门槛

### 16.1 自动化测试

- Rust 单元测试：状态机、预算、Schema、修复、权限、分块、融合和迁移。
- Rust 集成测试：Provider mock、MinerU 恢复、MCP transport、索引重建和备份恢复。
- 协议契约测试：Rust 序列化与 TypeScript 消费结构一致。
- 前端组件测试：权限、任务、引用、设置和错误状态。
- 端到端测试：首次启动、对话、PDF 导入、引用回答、重启恢复和导出。
- 架构测试：依赖方向、文件大小、Tauri 边界和禁止 Web API。
- 安全测试：路径穿越、凭据泄漏、恶意 Markdown、归档炸弹和 MCP 权限绕过。
- 钢铁评估：问答、检索、计算、数据映射、预测和优化回归。

### 16.2 性能基线

在公开记录的 Windows 中档测试机上满足：

- 冷启动 P95 不超过 3 秒，数据库和索引损坏恢复提示除外。
- 空闲内存目标不超过 300 MB。
- 10 万分块已加载场景，本地混合候选检索 P95 不超过 1 秒，不含网络重排。
- 10 万分块增量启动不做无条件全量扫描。
- 对话流式首字延迟如实拆分为客户端、Provider 和工具等待时间。
- 大型导入任务不阻塞 UI 交互。

性能目标如因硬件差异未达到，发布报告必须给出机器配置、数据规模和瓶颈，不能删除基线测试。

## 17. 发布工程与开源运营

### 17.1 CI/CD

- Windows 为阻断发布的平台；Linux/macOS 可并行支持，但不能降低 Windows 质量。
- CI 执行 Rust、TypeScript、契约、架构、安全和端到端测试。
- 发布产物包括安装包、便携包、校验和、签名、SBOM 和第三方 notices。
- Tauri 更新使用独立签名密钥，私钥只存在于发布密钥设施。
- 数据库和协议兼容矩阵随版本发布。

### 17.2 开源仓库

正式发布前必须具备：

- 中英文 README。
- 产品定位和边界说明。
- 架构文档和 `PROTOCOL.md`。
- 安全策略、隐私说明和漏洞报告流程。
- 贡献指南、行为准则和开发环境说明。
- 领域包、MCP 和 Skills 开发文档。
- 精心设计的 good first issue，包含背景、代码范围和验收标准。
- 可复现演示、截图、视频和钢铁案例研究。

案例指标至少覆盖：首次配置时间、PDF 到引用回答闭环、10 万分块检索性能、重启恢复和钢铁评估集表现。所有营销数字必须能由公开脚本复现。

## 18. 上游项目复用策略

| 项目 | 可借鉴内容 | 不直接复用的原因 |
| --- | --- | --- |
| Grok Build | typed tools、进度事件、权限和 workspace 边界 | xAI 内部 crate 多，编码代理假设重，Windows 仅 best-effort |
| Pi | 简洁 Agent loop、工具调度、Provider 归一化 | TypeScript runtime，不适合作为 Rust 内核 |
| DeepSeek-Reasonix | 配置、会话恢复、缓存、ACP 和社区文档 | Go 架构且产品侧重编码与研究工作流 |
| OpenCode | Provider UX、Plan/Build 权限模式、桌面产品交互 | TypeScript/Bun 体系和代码代理产品模型 |
| Goose | Rust MCP 集成和扩展管理 | 仍以通用开发智能体为中心，直接 fork 删除成本高 |

复用决策由第三方代码台账记录：来源 commit、许可证、复制或修改范围、负责人和替换测试。Apache 代码保留 NOTICE；MIT 代码保留版权声明。仅借鉴思想时采用 Bloomery 自有命名和实现，不进行逐行翻译。

## 19. 实施阶段与完成定义

阶段只表示依赖顺序，不表示对外发布版本：

1. 建立架构护栏、第三方台账和旧 Web 依赖清单。
2. 移除登录、自有后端、云任务和 Web API 兼容路径。
3. 建立存储迁移、OS 密钥、Provider 和持久化任务基础。
4. 完成本地知识库、MinerU、混合索引、重排和引用闭环。
5. 完成模块化 Rust Agent、事件协议、上下文和 Tool-Call Repair。
6. 完成工具权限、MCP、Skills 和领域包运行时。
7. 完成官方钢铁包、生产数据、模型推理、训练和优化能力。
8. 完成正式桌面信息架构、首次启动、诊断、导入导出和恢复。
9. 完成性能、安全、兼容、回归和故障注入测试。
10. 完成签名发布、更新、双语文档、贡献体系和可复现案例。

正式版只有一个完成定义：以上十个阶段全部完成，且第 20 节所有验收项通过。开发中可以生成内部构建用于测试，但不得将功能缺失的构建描述为 Bloomery 正式版。

## 20. 正式版验收清单

- Windows 10 和 Windows 11 全新环境可安装、升级和卸载。
- 用户配置一个 LLM Key 后，三分钟内可以完成首次对话。
- 应用运行不访问作者自有服务器，网络目的地可由用户配置解释。
- API Key 不出现在 SQLite、日志、崩溃信息、导出或诊断包中。
- 从 PDF 导入到带页码引用回答形成完整闭环。
- MinerU、索引、Agent 和分析任务在异常退出后可恢复。
- SiliconFlow 免费或 Pro 模型可以独立选择、测试和降级。
- 10 万分块检索达到性能基线，模型切换可安全重建索引。
- MCP 三种 transport、Bloomery Skills 和权限规则通过契约测试。
- 会话、知识库和完整数据备份可以导出、校验和恢复。
- 官方钢铁包通过版本化领域评估集。
- 安装包、更新清单、SBOM、校验和和签名齐全。
- 中英文 README、安全、贡献、协议和扩展文档齐全。
- 发布案例的质量和性能数字可在公开环境复现。

## 21. 计划规模

按照单一主开发者配合 AI、领域数据准备并行推进估算，完整工作量约为 28 至 36 个工程周。该数字用于暴露规模，不是压缩功能的截止日期。影响日历时间的主要变量是钢铁评估数据质量、复杂优化计算扩展、Windows 签名获取和真实工业用户测试。

后续详细实施计划必须把本规格拆为可独立验收的任务，每项写明具体文件范围、接口、迁移、测试命令和完成条件；不得用“后续完善”绕过本文能力。
