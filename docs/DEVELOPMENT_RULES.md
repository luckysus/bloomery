# Codex 开发纪律

## 每次修改前

1.  检查 Git 状态、目录、依赖、数据库迁移和已有实现。
2.  运行适用的基线构建/测试并记录错误。
3.  列出本次目标、涉及文件、风险和验收命令。
4.  采用最小变更，不删除用户数据。

## 禁止

-   未经确认重写整个仓库或更换技术栈；
-   只做静态 UI、假 API 或空按钮；
-   用随机数/延时假装模型、工具或 Agent 正在运行；
-   编造文献、预测结果或模型指标；
-   吞掉异常并返回成功；
-   将密钥、密码、令牌写入代码或日志；
-   未经确认清空数据库/覆盖文件；
-   让模型输出直接执行任意 shell/代码；
-   把隐藏推理链展示给用户。

## 工作流程

读文档和代码 → 制定小计划 → 实施 → 格式化/类型检查/lint/测试/构建 →
修复本次引入的问题 → 汇报实际结果与未完成项。

## 代码质量

Rust：明确错误类型、可取消异步任务、避免锁跨
await。TypeScript：严格类型，避免 any，统一 API
错误处理。Python：类型提示、输入校验、结构化日志。SQL：参数化、迁移、索引和事务。UI：复用组件并覆盖加载/空/错态。

## 完成定义

只有功能真实实现、适用测试通过、文档更新、Mock
范围清晰，才可标记完成。测试没运行必须说明原因。
