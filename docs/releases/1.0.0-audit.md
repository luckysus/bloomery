# Bloomery 1.0.0 Release Audit

审计日期：2026-08-12  
审计基线：`main` 分支当前提交  
审计结论：**尚不能声明正式 1.0.0 发布**

这份文档按发布设计和质量计划逐项记录当前证据。工程测试通过不等于正式发布完成；没有当前、直接、可复现证据的项目保持未完成状态。

## 结论摘要

| 状态 | 含义 |
| --- | --- |
| 已证明 | 当前源码、测试、脚本或产物直接提供了证据 |
| 部分证明 | 主要实现存在，但完整发布范围仍缺少一项或多项证据 |
| 未证明 | 没有足够的当前证据，不能打勾 |
| 发布阻断 | 在正式公开发布前必须解决 |

- ONNX 与源模型的完整公开 parity 证据；
- 计算 Worker 在正式签名发布包中的签名与干净机器验证；
- 完整钢铁案例研究从干净检出到最终报告的独立复现。

## Gate G：桌面产品体验

### 已证明

- 首次启动、工作台、聊天、知识库、分析、扩展、设置和诊断页面存在；
- Provider 降级、权限请求、任务恢复、引用和错误状态有专门 UI；
- 会话导出与完整备份/恢复不导出明文密钥；
- 前端运行时边界、窗口尺寸相关自动化测试和生产构建通过。

### 尚未证明

- 新用户在全新 Windows 用户配置文件中从安装到首次对话三分钟内完成；
- Windows 10/11 两个版本的完整视觉与交互手工验收；
- Unicode 用户名、非默认数据路径和真实升级路径的完整证据。

## 不应做的发布声明

在上述阻断项关闭前，不应使用以下表述：

- “Bloomery 1.0.0 正式版已发布”；
- “Windows 10/11 已完整兼容”；
- “安装包已签名”；
- “更新器已完成正式验证”；
- “完全离线”；
- “所有钢铁工业指标都已通过真实生产数据验证”。

当前正确表述是：**Bloomery main 分支是面向公开发布目标构建的 Windows 工程版本；核心本地智能体和发布候选流程已具备，但正式签名、Windows 11 和最终发布审计仍未完成。**

## 下一步验收顺序

1. 在当前 Windows 10 上补齐完整安装、升级、降级、卸载、Unicode 用户名和非默认数据路径矩阵。
2. 在真实 Windows 11 环境重复同一矩阵。
3. 补齐 cold start、idle memory、100k-row import、事件吞吐和大对话回放基准。
4. 配置受保护的正式签名环境，生成并验证安装包、领域包和 updater 清单签名。
5. 从 clean checkout 和 fresh Windows profile 运行完整 `release-check.ps1`。
6. 完成公开钢铁案例研究，再逐项更新本审计和路线图复选框。

每一项关闭都必须附带命令、提交 SHA、产物路径或手工环境记录；仅凭“代码已实现”不能关闭发布 Gate。
