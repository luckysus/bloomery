# Bloomery 1.0.0 Release Audit

审计日期：2026-08-13
审计基线：`main` 分支当前提交  
审计结论：**尚不能声明正式 1.0.0 发布**

这份文档按发布设计和质量计划逐项记录当前证据。工程测试通过不等于正式发布完成；没有当前、直接、可复现证据的项目保持未完成状态。

## 结论摘要

| 状态 | 含义 |
| --- | --- |
| 已证明 | 当前源码、测试、脚本或产物直接提供了证据 |
| 部分证明 | 主要实现存在，但完整发布范围仍缺少一项或多项证据 |
| 未证明 | 没有足够的当前证据，不能打勾 |
| 发布阻断 | 在正式公开发布前必须解决 |

### 本轮修复证据（2026-08-13）

- MCP 配置与凭据更新现在以同一条应用级补偿流程提交；数据库保存失败、凭据部分写入失败和凭据删除失败都会恢复此前凭据快照。
- MCP 编辑时会同时清理旧环境变量名称对应的凭据，避免重命名后遗留系统凭据。
- 多个不同领域包可以同时激活；聊天提示词、内置工具白名单和本地检索证据上限会按所有活动领域包计算。
- 旧的单领域提示词包装函数已删除，生产调用统一使用复数领域 API。
- 本轮验证：Rust 全量 `110` 个主库测试及所有集成目标通过；MCP 回滚测试 `2/2`、领域包测试 `20/20`、领域工具测试 `3/3`、桌面提示词测试 `13/13`；前端测试 `93/93`；Rust 格式、发布脚本契约、前端边界和安全门禁通过。
- 本轮完整 `scripts/release-check.ps1 -AllowDirty -Offline` 通过：前端、Rust、Worker `74/74`、钢铁评测 `4/4`、迁移和备份生命周期检查均通过，最终输出为 `Release checks passed for Bloomery 0.1.0.`；该结果仍不包含正式签名、Windows 11 和 clean checkout/fresh profile 证据。
- 本轮新增 Windows 生命周期矩阵工具、契约测试和验收文档。旧提交 `a6c0e43` 的未签名工程包已在当前 Windows 10 完成全新安装 smoke，覆盖 Unicode 安装路径、非默认数据目录、启动、卸载和数据保留；报告为 `artifacts/Bloomery-0.1.0-release-repaired-20260813/windows-10-install-smoke-matrix.json`，仅作历史工程包证据，不能关闭当前版本或 Windows 11 的发布门禁。

## 不应做的发布声明

在上述阻断项关闭前，不应使用以下表述：

- “Bloomery 1.0.0 正式版已发布”；
- “Windows 10/11 已完整兼容”；
- “安装包已签名”；
- “更新器已完成正式验证”；
- “完全离线”；
- “所有钢铁工业指标都已通过真实生产数据验证”。

当前正确表述是：**Bloomery main 分支是面向公开发布目标构建的 Windows 工程版本；核心本地智能体和发布候选流程已具备，但正式签名、Windows 11 和最终发布审计仍未完成。**

## 下一步验收顺序

1. 使用当前版本和真实旧版本安装包，在 Windows 10 执行完整安装、升级、降级、卸载、Unicode 用户名和非默认数据路径矩阵。
2. 在真实 Windows 11 环境重复同一矩阵。
3. 在真实 Windows 11 环境重复安装、升级、卸载、数据保留和性能矩阵。
4. 配置受保护的正式签名环境，生成并验证安装包、领域包和 updater 清单签名。
5. 从 clean checkout 和 fresh Windows profile 运行完整 `release-check.ps1`。
6. 完成公开钢铁案例研究，再逐项更新本审计和路线图复选框。

每一项关闭都必须附带命令、提交 SHA、产物路径或手工环境记录；仅凭“代码已实现”不能关闭发布 Gate。
